자동화 범위는 사전 계정·RG·사용자 RBAC·RP까지입니다. Foundry·프로젝트·모델·Log Analytics·App Insights, 모델 그룹/TPM 설정, MFA/조건부 액세스 변경, SE 역할 부여, 프로젝트 MI 후속 권한, 자동 종료·삭제는 포함하지 않습니다. 필요한 리소스는 참가자가 본인 RG 안에서 생성합니다. 인원 수 입력은 Foundry 자원 수·쿼터·부하 수용을 보장하지 않습니다.

재실행·실패 복구 기준

  1. 같은 작업의 재시도: 동일한 설정·작업 폴더·비공개 기록으로 다시 계획 → --apply → 검증합니다. 기존 계정·역할을 중복 생성하거나 초기 암호를 리셋하지 않습니다. 원격 사용자 생성 POST는 응답 유실 시 자동 재전송하지 않습니다.
  2. 충돌·추가 권한: 사용자 소유권 마커·RG 태그·이름·지역이 다르거나 불필요한 권한이 있으면 중단합니다. 기존 자원을 임의로 채택·수정하거나 권한을 자동 회수하지 않습니다. SE가 원인을 검토하고 승인된 별도 조치를 수행합니다.
  3. 기록 유실: 기존 계정을 발견했는데 암호 복구 기록이 없으면 자동 재설정하지 않습니다. 승인된 백업을 복원하거나 별도 계정 복구 절차를 밟습니다. 생성 후 인원·지역 등 설정을 바꾸거나 기록을 지워 재시도하지 않습니다.
  4. 새 행사: 새 고유 workshopId로 준비합니다. 같은 워크샵은 한 SE가 한 실행 폴더에서 순차 실행하며 다른 기기에서 동시에 적용하지 않습니다.
  5. 전파·조회 오류: 권한 반영에는 시간이 걸릴 수 있습니다. 401/403은 로그인·Graph 동의·SE 역할·Scope를 확인하고, 전파 대기 후 검증을 다시 실행합니다. 오류를 숨기거나 참가자에게 더 높은 역할을 주지 않습니다.
Azure를 변경하지 않는 스크립트 자체 테스트·공식 API 근거
