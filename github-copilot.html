STEP 01 · WHAT IS GITHUB COPILOT

GitHub Copilot은 코딩을 돕는 AI 도우미입니다. 한 계정으로 여러 곳에서 씁니다.

질문에 답하고, 코드를 제안하고, 내가 승인하면 파일 수정·명령 실행까지 대신합니다. 답과 변경은 항상 내가 확인합니다.

묻기

설명해 줍니다

코드·오류 메시지·용어를 쉬운 말로 풀어 줍니다. 예: “이 오류가 무슨 뜻이야?”

제안

코드를 써 줍니다

하려는 일을 말하면 코드를 제안합니다. 편집기에서는 입력하는 중에 이어질 코드를 회색 글씨로 보여 줍니다.

대행

작업을 진행합니다

에이전트가 여러 단계를 스스로 진행합니다. 파일 수정·명령 실행은 내 승인을 받은 뒤에 합니다.

  1. 내 GitHub 계정사용자명 · 이메일 인증
  2. 조직 가입초대 수락 / 자가가입
  3. Copilot 좌석운영자가 내 사용자명에 배정

STEP 02 · BEFORE YOU START

내 GitHub 계정과 운영자에게 받을 값을 확인하세요.

용도사용할 계정혼동하지 않는 기준
Azure·Foundry 실습배정된 Internal Guest UPNAzure 로그인·MFA용입니다. GitHub 계정이나 이메일 수신함이 만들어지지 않습니다.
GitHub 조직·Copilot 사용본인 개인 GitHub.com 계정조직 가입 수락과 브라우저·Codespaces·VS Code·Copilot CLI·Copilot 앱 로그인에서 같은 사용자명을 씁니다. 인증된 본인 이메일과 GitHub 2FA를 준비하세요.

계정이 있다면 · 3가지만 확인

이미 쓰는 개인 계정을 그대로 씁니다.

  1. github.com/login으로 로그인하고 오른쪽 위 프로필을 열어 사용자명(username)을 메모합니다. 표시 이름과 다릅니다.
  2. Settings → Emails에서 초대받을 이메일이 인증(verified)되어 있는지 확인합니다.
  3. Settings → Password and authentication에서 2FA가 켜져 있는지 확인합니다. 조직이 요구할 수 있습니다.

개인 Copilot 유료 플랜(Pro·Pro+·Max)을 쓰는 계정이라면 04의 안내를 먼저 읽고 운영자와 상의하세요.

계정이 없다면 · 약 5분

개인 GitHub 계정을 만듭니다.

  1. github.com/signup을 열고 이메일로 가입합니다. Google·Apple 계정으로 이어서 가입할 수도 있습니다. 메일을 받을 수 있는 본인 이메일을 쓰세요.
  2. 화면 안내에 따라 암호와 사용자명(username)을 정합니다. 초대와 Copilot 좌석 배정에 쓰이니 메모해 둡니다.
  3. 받은 인증 코드·링크로 이메일을 인증합니다. 이메일 초대는 인증된 같은 이메일이 있어야 수락됩니다.
  4. GitHub 2FA를 켜고 복구 코드는 본인만 보관합니다.

가입 오류(This email can’t be used 등)는 막히면 확인을 보세요. 공식 계정 만들기 ↗

운영자의 행사 안내에서 아래 다섯 가지를 받아 두세요.

  1. 조직과 가입 방법: 조직 URL, 초대 이메일 또는 비공개 자가가입 링크·QR.
  2. Copilot 제공 방식: 허용 모델·사용 한도. 개인 Copilot 유료 플랜이 있다면 운영자에게 미리 알립니다.
  3. 저장소·환경: 실습 저장소·브랜치, 그리고 쓸 곳(브라우저·Codespaces·VS Code·Copilot CLI·Copilot 앱 중 어디인지).
  4. 일정: 링크 만료, 행사 시각, 조직·산출물 삭제 예정일과 시간대.
  5. 지원·보존: 문의 경로, 산출물 보존 위치.
  1. 계정 확인개인 GitHub 사용자명
  2. 조직 가입초대 수락 / 자가가입
  3. 권한 확인조직 Copilot
  4. 환경 선택다섯 곳 중 1곳
  5. 질문 실행실제 응답 확인
이 가이드는 개인 계정을 초대하는 조직 기준입니다. 실습 조직이 Enterprise Managed Users라면 개인 계정으로 가입하지 말고 운영자가 준 관리형 계정 절차를 따르세요.

본인 개인 GitHub 계정으로 로그인해 프로필의 사용자명(username)을 확인합니다. 계정이 없다면 02의 ‘계정이 없다면’에서 계정 만들기·이메일 인증부터 끝냅니다.

초대 수락 · 초대 이메일을 받은 경우

받은 초대를 본인 계정으로 수락합니다.

  1. 초대 이메일의 View invitation 또는 운영자가 준 조직 URL을 엽니다.
  2. GitHub 로그인 요구가 나오면 초대받은 본인 개인 계정으로 로그인합니다. Entra UPN으로 로그인하지 않습니다.
  3. 사용자명·조직명을 확인하고 Join / Accept invitation을 선택합니다.

초대는 7일 후 만료됩니다. 이메일 초대는 내 계정에 인증된 같은 이메일이 있어야 수락됩니다. 공식 초대·수락 기준 ↗

본인 계정 인증 → 초대 요청 → 초대 수락

  1. 운영자가 비공개로 전달한 링크·QR을 엽니다. 조직명·가입 가능 기간을 확인합니다.
  2. 본인 개인 GitHub 계정으로 인증하고 사용자명을 확인합니다. 다른 계정이면 로그아웃하고 다시 인증합니다.

  5. 초대가 발송되면 이메일 또는 조직 URL에서 초대 수락을 완료합니다. 요청만으로는 멤버가 아닙니다.

초대가 안 보이거나 2FA·SSO를 요구하면

STEP 04 · MEMBERSHIP IS NOT A COPILOT LICENSE

가입했어도 Copilot은 별도 권한입니다. 직접 확인하세요.

  1. 운영자가 같은 GitHub 사용자명에 조직 Copilot 권한(좌석)을 배정했는지 확인합니다. 배정은 운영자가 하는 일입니다.
  2. 같은 계정에서 Settings → Copilot을 열고 새로고침하거나 다시 로그인합니다. 내 계정에서 켜진 기능은 Copilot features 페이지에서 볼 수 있습니다.
  3. Copilot Free만 보이거나 개인 결제를 요구하면 직접 유료 가입하지 말고 사용자명과 화면 상태만 운영자에게 전달합니다.
대상 조직: <운영자가 안내한 조직명>
GitHub 사용자명: <본인 username>
요청: 조직 Copilot 좌석 배정 여부 확인 (Copilot CLI·GitHub Copilot 앱을 쓴다면 해당 정책 허용 여부도 확인)
좌석

조직에 가입했지만 Copilot 권한이 없을 때

  1. 가입한 정확한 조직과 내 사용자명을 확인합니다.
  2. Copilot 설정에 Ask admin for access 버튼이 보이면 눌러 신청합니다. 보이지 않으면 승인된 문의 경로로 운영자에게 요청합니다.
  3. 운영자가 승인·배정한 뒤 새로고침하거나 다시 로그인합니다.

구분: 이 신청은 Copilot 사용 권한 요청입니다. 조직 가입 요청과 다르며, 신청만으로 Copilot이 켜지지 않습니다.

개인 Copilot 유료 플랜(Pro·Pro+·Max)을 쓰고 있다면: 조직 좌석을 받는 순간 개인 플랜이 자동 취소되고 일할 환불될 수 있습니다. 유지해야 한다면 가입 전에 운영자와 상의하세요. 단순 조직 가입은 영향이 없고 좌석 배정이 기준입니다. 공식 라이선스 기준 ↗
채팅이 된다고 조직 권한이 확인된 것은 아닙니다. 개인 Free/Pro로도 답할 수 있으므로 운영자의 좌석 배정과 따로 확인하세요.
좌석 하나로 모든 곳에서 씁니다. 브라우저·Codespaces·VS Code·Copilot CLI·Copilot 앱은 같은 조직 좌석을 쓰며 따로 구매하지 않습니다. 다만 조직 정책에서 브라우저(클라우드)·CLI·앱 사용이 각각 허용되어 있어야 하며, 허용 여부는 운영자가 확인합니다.

Copilot CLI에서 시작 설치 필요약 10분 · 터미널

Copilot CLI는 터미널에서 Copilot과 대화하는 도구입니다. 시작하기 전에 운영자가 조직의 Copilot CLI 정책을 허용했는지 확인하세요. 좌석이 있어도 정책이 꺼져 있으면 쓸 수 없습니다.

터미널이 처음이라면 · 여는 법과 기본 명령
  1. macOS: ⌘+Space → Terminal 입력 → Enter. Windows: 시작 메뉴에서 PowerShell 7(또는 Windows Terminal)을 엽니다. VS Code: Terminal → New Terminal.
  2. 현재 위치는 pwd, 파일 목록은 ls, 폴더 이동은 cd 폴더이름입니다. Windows PowerShell에서도 같은 이름으로 동작합니다.
  3. 명령은 한 줄씩 붙여 넣고 Enter를 누릅니다. 출처를 모르는 명령은 실행하지 않습니다.
  1. 설치합니다. 내 환경에 맞는 한 줄을 터미널에 붙여 넣습니다.
    환경설치 명령
    Windowswinget install GitHub.Copilot
    macOS · Linuxbrew install --cask copilot-cli (Homebrew)
    모든 OSnpm install -g @github/copilot (Node.js 22 이상)

    Windows는 PowerShell 6 이상이 필요합니다. 기본 ‘Windows PowerShell’(5.1)은 해당하지 않으니 winget install --id Microsoft.PowerShell --source winget로 PowerShell 7을 설치한 뒤 PowerShell 7에서 위 명령을 실행하세요.

  2. 설치를 확인합니다. copilot --version을 실행해 버전이 나오면 성공입니다. “찾을 수 없다”는 메시지가 나오면 터미널을 닫고 새로 연 뒤 다시 실행합니다.
  3. 작업 폴더로 이동합니다. 질문만 해 볼 때는 새 폴더를 만들어 들어갑니다. 코드 실습이면 운영자가 준 저장소 폴더로 이동합니다. 홈 폴더(~)에서는 실행하지 마세요. 
    mkdir copilot-practice
cd copilot-practice
  4. copilot을 실행합니다. 처음 보는 폴더에서는 아래와 같은 폴더 신뢰 확인이 나옵니다. 이번 세션만 허용하는 1. Yes를 고릅니다. 2. Yes, and remember…는 운영자가 준 실습 폴더에서만 고르고, 확신이 없으면 3. No(Esc)로 종료합니다.
  5. 로그인합니다. 프롬프트에 /login을 입력하고 Enter를 누릅니다. 계정 종류는 GitHub.com, 방식은 Sign in with your browser를 고릅니다. 브라우저에서 내 개인 GitHub 계정으로 Authorize GitHub Copilot CLI를 누르고, 조직 SSO 안내가 나오면 조직 옆 Authorize도 누릅니다. 터미널에 Signed in successfully as 내사용자명이 나오면 성공입니다.

    브라우저가 열리지 않으면 터미널에 표시된 URL을 직접 열거나 Sign in with a device code를 고르고 github.com/login/device에 화면의 1회용 코드를 입력합니다. Codespaces·SSH 같은 원격 터미널은 처음부터 device code 방식이 열립니다.

  6. 질문을 입력합니다. 입력줄에 06의 질문을 붙여 넣고 Enter를 누릅니다. Copilot이 파일 수정이나 명령 실행 전에 승인을 물으면 내용을 읽고 Yes(이번 한 번)만 선택합니다. 모르면 No를 고르고 다른 방법을 지시합니다. ‘다시 묻지 않기’·‘세션 동안 승인’ 류는 고르지 않습니다.
  7. 확인하고 종료합니다. /user로 로그인한 계정이 내 사용자명인지 확인합니다. 끝낼 때는 /exit를 입력합니다. Ctrl+C를 두 번 눌러도 종료됩니다.

완료 상태: 질문에 대한 답이 터미널에 출력되고 /user가 내 사용자명을 보여 줌 → 06 질문 1개 실행.

GitHub Copilot 앱에서 시작 설치 필요약 10분 · 데스크톱

GitHub Copilot 앱은 데스크톱 에이전트 앱입니다. 저장소별 세션을 여러 개 나란히 돌리고 변경 확인·PR까지 한 곳에서 합니다. 시작하기 전에 운영자가 조직의 GitHub Copilot app 정책(CLI 정책과 별개)을 허용했는지 확인하세요. 지원 OS는 macOS·Windows·Linux이며 Git이 필요합니다.

  1. 내 PC에 맞는 설치 파일을 내려받습니다.
    내 PC내려받기
    macOS · Apple Silicon.dmg 내려받기
    macOS · Intel.dmg 내려받기
    Windows · x64.exe 내려받기
    Windows · Arm.exe 내려받기
    Linux · x64.AppImage 내려받기
    Linux · Arm.AppImage 내려받기

    Mac의 칩이 헷갈리면 Apple 메뉴 → 이 Mac에 관하여에서 ‘칩’이 Apple M…이면 Apple Silicon, ‘프로세서’가 Intel이면 Intel입니다. 다른 빌드는 Releases ↗, 공식 안내는 다운로드 페이지 ↗에 있습니다.

  2. 설치하고 앱을 엽니다. macOS는 .dmg를 열어 앱을 Applications로 옮긴 뒤 실행하고, Windows는 .exe 설치 안내를 따릅니다. 회사 PC의 보안 정책으로 설치가 막히면 우회하지 말고 운영자에게 알린 뒤 브라우저·Codespaces로 진행합니다.
  3. 로그인합니다. Sign in to GitHub를 누르고 안내에 따라 내 개인 GitHub 계정으로 로그인·승인합니다. 이어서 “Copilot 플랜이 없다”며 플랜 가입이나 자체 모델 공급자(BYOK) 선택이 나오면 가입하거나 API 키를 넣지 말고 멈춰서 운영자에게 알립니다. 좌석·앱 정책·로그인 계정을 확인해야 합니다.
  4. 초기 설정을 마칩니다. 저장소 선택 화면에서는 최근 활동 기반 목록에서 실습 저장소를 고르거나 로컬 폴더를 추가합니다. 모르면 건너뛰어도 됩니다. 테마를 고르고 온보딩을 마치면 앱이 열립니다.
  5. 질문만 해 볼 때는 Chats를 씁니다. 왼쪽 사이드바의 Chats에서 대화를 시작하고 질문을 입력합니다. 저장소나 브랜치가 필요 없습니다.
  6. 코드 실습이면 세션을 시작합니다. 사이드바 Sessions 옆 + → Open local folder(이미 받은 폴더), Add GitHub repository(GitHub에서 받기), Clone repository(URL로 받기) 중 하나로 저장소를 연결합니다. 다시 + → Start session in에서 저장소를 고릅니다.
  7. 입력창 아래 설정을 확인합니다. Environment는 This computer(Cloud는 운영자가 안내한 경우에만), 세션 모드는 Interactive입니다. 모드 메뉴의 Tool permissions는 Ask every time을 고릅니다.
  8. 프롬프트를 입력합니다. 질문을 붙여 넣고 Enter를 누릅니다. 에이전트가 파일을 바꾸면 입력창 위 Changes에서 변경 내용을 확인합니다. Create PR은 실습 지시가 있을 때만 누릅니다.

완료 상태: Chats 또는 세션 대화에 질문에 대한 답이 표시됨 → 06 질문 1개 실행.

Projects·Automations·Autopilot은 이 워크샵에서 쓰지 않아도 됩니다. 화면 이름은 앱 버전에 따라 다를 수 있습니다. 공식: 앱 빠른 시작 ↗ · 앱 소개 ↗

Codespaces·VS Code·Copilot CLI·Copilot 앱에서 실습 저장소를 연 채로 아래 질문을 입력합니다. CLI는 저장소 폴더에서 copilot을 실행하고, 앱은 그 저장소의 세션에서 입력합니다. 답변의 경로·실행 방법을 실제 파일과 대조하세요. 웹 채팅의 일반 답변만으로는 IDE·CLI·앱의 로그인과 저장소 접근이 확인되지 않습니다.

이 저장소의 README와 파일 구조를 읽고 실행 방법과 가장 먼저 살펴볼 파일을 3줄로 설명해줘. 아직 파일을 수정하거나 명령을 실행하지 마.

이후의 코드 변경·명령은 실습 지시에 따라 검토한 뒤 진행합니다. 개인 토큰·Azure 키·고객 실데이터를 채팅에 넣지 않습니다.

Foundry와 Copilot의 한도는 별개입니다. Foundry의 gpt-6.1-terra TPM 배분은 모델 배포용이며 Copilot 좌석·사용 한도와 공유되지 않습니다. Copilot 모델은 조직이 허용한 목록과 실습 안내를 따릅니다.
공개·합성 데이터만 사용하세요. 고객 실데이터·비공개 코드·암호·MFA 코드·API 키·연결 문자열을 질문에 넣지 않습니다. 오류 화면은 민감 정보를 가린 뒤 승인된 지원 경로로만 전달합니다.

STEP 07 · FIVE HABITS FOR USING COPILOT WELL

첫 응답 다음은 기본기 다섯 가지입니다. 3분이면 읽습니다.

습관이렇게 하세요
1 · 구체적으로 묻기목표·상황·원하는 형식을 한 문장에 담습니다. 예: “초보자에게 3줄로”, “표로”, “아직 파일은 바꾸지 마.”
2 · 이어서 묻기한 번에 다 시키지 말고 답을 본 뒤 후속 질문으로 좁힙니다. 같은 대화(세션) 안에서는 앞 내용이 이어집니다.
3 · 가리키기CLI·앱에서는 @파일경로로 파일을 지정하고, 앱에서는 #으로 이슈를 참조하고 /로 명령을 고릅니다. 브라우저에서도 @로 파일·이슈·PR을 가리킬 수 있습니다.
4 · 모드 고르기이해·질문은 기본 모드(앱은 Interactive), 큰 변경은 Plan으로 계획부터 확인합니다. 승인 없이 끝까지 진행하는 Autopilot은 쓰지 않습니다.
5 · 검토하고 승인하기AI의 답은 틀릴 수 있습니다. 변경은 diff로 확인하고, 승인 요청은 내용을 읽고 판단합니다. 비밀·고객 데이터는 넣지 않습니다.
아쉬운 질문좋은 질문 (예시)
“429 해결해줘”“Microsoft Foundry 모델 호출에서 HTTP 429가 났어. TPM·RPM 중 무엇부터 확인해야 하는지 초보자용 3단계로 알려줘.”
“이 코드 고쳐줘”“@src/app.py의 parse_config가 빈 파일에서 예외를 내. 원인을 설명하고 수정안을 diff로 보여줘. 아직 파일은 바꾸지 마.”

사용량은 AI 크레딧으로 계산됩니다. 질문과 에이전트 작업은 조직(또는 개인 플랜)의 AI 크레딧을 쓰며, 긴 에이전트 작업·고성능 모델일수록 더 많이 씁니다. 같은 요청을 반복 실행하지 말고, 허용 모델과 한도는 운영자 안내를 따르세요.

STEP 08 · SAVE BEFORE THE TEMPORARY ENVIRONMENT ENDS

마무리: 산출물을 보존하고, 일정을 확인합니다.

  1. 남길 변경은 운영자가 허용한 브랜치에 commit·push하고 실제 저장소에서 확인합니다. 임시 조직 밖에 보존해야 하면 승인된 비공개 위치를 쓰고, 코드·고객 자료를 임의로 공개하지 않습니다.
  2. 사용한 Codespace는 Stop합니다. 브라우저 탭을 닫아도 유휴 제한(기본 30분)까지 실행되며, 정지 후에도 저장 공간 비용이 남을 수 있습니다.
  3. CLI·앱 정리: Copilot CLI는 /exit로 종료하고, 앱의 세션은 더 쓰지 않으면 닫습니다. 파일이 바뀌었다면 /diff(CLI)나 Changes(앱)로 확인한 뒤 실습 지시에 따라 commit하거나 되돌립니다.
  4. 공용·대여 PC라면 로그아웃합니다. 브라우저의 GitHub, VS Code(Accounts → Sign out), Copilot CLI(/logout)에서 로그아웃합니다. 앱은 로그아웃 절차를 이 가이드에서 확인하지 못했으므로 공용 PC에는 설치하지 마세요.
  5. 좌석·조직·저장소·Codespaces의 삭제와 보존은 운영자 정책을 따릅니다. 임시 조직 삭제는 내 개인 GitHub 계정 삭제와 다릅니다.

CLI /login이 끝나지 않음터미널에 표시된 URL을 직접 열거나 /login에서 Sign in with a device code를 골라 github.com/login/device에 코드를 입력합니다. 조직 SSO 안내가 보이면 조직 옆 Authorize를 누릅니다.

CLI가 다른 계정으로 로그인됨/user로 현재 계정을 확인하고, /user switch 또는 /logout 후 /login으로 조직 좌석을 받은 계정에 다시 로그인합니다. GH_TOKEN·GITHUB_TOKEN 같은 환경 변수가 있으면 로그인보다 우선하니, 토큰 값이 아닌 설정 여부만 확인합니다.
CLI에서 모델이 안 보임/model로 내게 허용된 모델을 확인합니다. 목록이 비었거나 오류가 나면 모델 정책이나 좌석 문제일 수 있으니 운영자에게 확인합니다.
Copilot 앱이 설치·실행 안 됨내 PC에 맞는 파일(macOS Apple Silicon/Intel, Windows x64/Arm)을 받았는지 확인합니다. 회사 PC의 설치 제한이나 보안 프로그램이면 우회하지 말고 운영자에게 알린 뒤 브라우저·Codespaces로 진행합니다.

앱에서 저장소가 안 보임Git 설치와 저장소 접근 권한(조직 가입·SSO 승인)을 확인합니다. 저장소 URL이 있다면 Clone repository로 받습니다. 계속 안 되면 운영자에게 알립니다.
에이전트가 파일을 바꿈먼저 변경 내용을 확인합니다(CLI /diff, 앱 Changes). commit하지 않았다면 실습 지시에 따라 되돌리거나 운영자에게 요청합니다. CLI는 /rewind로 대화와 Copilot이 바꾼 파일을 이전 시점으로 되돌릴 수 있습니다.
한도·모델 제한 메시지남은 한도와 허용 모델은 운영자 안내를 따릅니다. 같은 요청을 반복하지 말고 질문을 줄이거나 가벼운 모델로 바꿔 보고, 계속되면 운영자에게 확인합니다.
개인 Copilot 구독이 바뀜조직 좌석을 받으면 개인 Pro·Pro+·Max가 자동 취소·일할 환불될 수 있습니다. Settings → Copilot과 공식 안내로 확인하고 운영자와 상의합니다. 좌석을 제거하면 개인 플랜이 복구된다고 가정하지 않습니다.

문의에는 GitHub 사용자명·대상 조직·진행 경로(초대 수락 / 자가가입)·선택 환경(CLI·앱이면 버전)·발생 시각·민감 정보를 가린 화면만 포함합니다. 암호·2FA 코드·토큰·서명된 링크는 보내지 않습니다.

기준일 2026.11.10 · 메뉴 이름과 정책은 GitHub 업데이트로 바뀔 수 있습니다. Copilot CLI는 1.0.108 기준이며, Copilot 앱 화면은 공식 문서 기준으로 안내합니다. 이 페이지는 가입·구매·권한 부여를 실행하지 않으며, 실제 링크·저장소·종료일은 운영자 안내를 따릅니다. 운영자는 GitHub 운영자 가이드를 참조하세요.
