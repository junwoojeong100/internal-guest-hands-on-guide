STEP 01 · CHOOSE ONE JOIN PATH

조직에 가입하세요. A 또는 B를 선택합니다.

먼저 GitHub에 본인 개인 계정으로 로그인하고 프로필의 사용자명(username)을 확인합니다. 계정이 없다면 개인 계정 생성과 이메일 인증을 본인이 완료합니다. 운영자에게 전달할 값은 GitHub 사용자명이며, 암호·2FA 코드·토큰은 전달하지 않습니다.

A · 관리자가 먼저 초대한 경우

받은 초대를 직접 수락합니다.

  1. 운영자가 보낸 GitHub 초대 이메일 또는 초대 링크를 엽니다.
  2. 대상 조직명과 로그인한 본인 사용자명을 확인하고 Join / Accept invitation을 선택합니다.
  3. 내 Organizations에서 조직 멤버십을 확인하고 운영자에게 수락 완료를 알립니다.
다음 · Copilot 권한 확인 →

B · 사용자가 먼저 가입을 신청하는 경우

참여 신청 후, 승인된 초대를 수락합니다.

  1. 운영자가 안내한 가입 신청 링크 또는 승인된 문의 경로로 대상 조직명과 본인 GitHub 사용자명을 제출합니다. 아래 문구를 사용할 수 있습니다.
  2. 관리자가 참가 여부·계정을 확인하고 승인 후 GitHub 조직 초대를 보낼 때까지 기다립니다.
  3. 초대를 받으면 A의 초대 수락 절차를 완료합니다. 신청 제출만으로 가입·Copilot 권한이 생기지는 않습니다.
GitHub 조직 가입 신청

신청 목적: 워크샵 참여 및 조직 제공 Copilot 사용
일반 GitHub 조직은 초대 수락으로 가입합니다. B는 사용자가 신청을 먼저 시작하는 경로이며, 이 페이지가 신청을 자동 제출하거나 조직 가입을 승인하지는 않습니다. 공개 조직 화면을 열거나 저장소를 fork하는 것만으로 멤버가 되지 않습니다.
초대 수락 전 확인: 초대는 7일 후 만료됩니다. 이메일로 초대받았다면 그 주소가 본인 GitHub 계정의 인증된 이메일이어야 합니다. 조직이 2FA를 요구하면 본인이 먼저 등록합니다. GitHub 2FA는 실습용 Entra MFA와 별개입니다. 조직 SSO 안내가 표시되면 운영자가 승인한 인증 절차를 따릅니다.

STEP 02 · MEMBERSHIP IS NOT A COPILOT LICENSE

운영자가 배정한 Copilot 사용 권한을 확인합니다.

  1. 조직 가입을 마친 같은 GitHub 사용자명에 Copilot Business/Enterprise 좌석이 배정되었는지 운영자에게 확인합니다. 좌석 배정은 관리자 작업입니다.
  2. GitHub 프로필 → Settings → Billing & licensing → Licensing에서 현재 Copilot 플랜·권한을 확인합니다. 기존 화면에서는 Plans and usage로 표시될 수 있습니다. 조직 제공 권한이 불명확하면 운영자가 좌석 목록을 대조합니다.
  3. 배정 후 페이지를 새로고침하거나 재로그인합니다. Copilot Free만 보이거나 개인 결제를 요구하면 직접 유료 가입하지 말고 운영자에게 사용자명과 화면의 상태만 전달합니다.
채팅이 된다는 것만으로 조직 좌석이 확인되지는 않습니다. 개인 Free/Pro로도 응답할 수 있으므로 조직 멤버십과 운영자의 좌석 배정을 따로 확인합니다.

ADMIN ONLY · INVITE, ASSIGN AND VERIFY

관리자 준비 · 초대와 Copilot 좌석은 별도입니다.

개인 계정을 멤버로 초대하는 일반 GitHub 조직 기준입니다. Enterprise Managed Users는 SCIM으로 계정을 프로비저닝하므로 이 가입 절차를 적용하지 않습니다. 조직명·가입 신청 링크/문의 경로·지원 담당·사용 종료 정책을 참가자에게 먼저 전달합니다.

  1. A / B 접수: A는 참가자 사용자명으로 먼저 초대합니다. B는 승인된 신청 경로에서 사용자명을 받아 참가 여부를 확인한 뒤 승인·초대합니다. 공개 사이트·공개 이슈에 고객 명단을 모으지 않습니다.
  2. 조직 초대: 조직 → People → Invite member → 정확한 사용자명 → Member → Send invitation. 본인 수락을 확인합니다. 기존 저장소의 기본 접근 권한·팀을 점검해 고객에게 불필요한 접근이나 Owner 권한을 주지 않습니다. 초대 발송 한도와 조직 멤버 라이선스도 확인합니다.
  3. Copilot 좌석: 승인된 Copilot Business/Enterprise 사용 환경에서 조직 → Settings → Copilot → Access → 필요 시 Allow this organization to assign seats → Start adding seats → Purchase for selected members → Users and teams에서 참가자 선택 → Continue to purchase → Purchase seats. 기존 화면에 따라 추가 버튼 이름은 달라질 수 있으므로 실제 할당 목록을 확인합니다.
  4. 정책·실행: Settings → Copilot → Policies에서 Copilot in GitHub.com이 허용되는지 확인합니다. 상위 엔터프라이즈 정책은 조직에서 덮어쓸 수 없습니다. 테스트 참가자 계정으로 가입·좌석·브라우저 질문 응답을 인계 전에 확인합니다.
  5. 비용·종료: 좌석은 사용 시작이 아니라 배정 시점부터 과금되므로 승인된 참가자만 선택합니다. 워크샵 종료 후 승인된 정책에 따라 Copilot 좌석과 임시 조직 멤버십을 회수하고 저장소·기록 보존을 처리합니다. 5시간 일정만으로 자동 종료되지 않으며 고객의 개인 GitHub 계정은 삭제하지 않습니다.
