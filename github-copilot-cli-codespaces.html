0시작 전에

두 계정의 역할과 준비물을 먼저 맞춰 둡니다. 이 실습에서 가장 흔한 실수는 “B로 로그인한 줄 알았는데 A로 로그인됨”입니다.

이 가이드의 전제: A와 B는 서로 다른 GitHub 계정입니다

Codespace를 만든 계정(A)과 Copilot CLI에 로그인할 계정(B)이 다른 상황을 다룹니다. 예를 들어 개인 계정으로 Codespace를 만들고, Copilot 라이선스가 있는 다른 계정으로 CLI를 쓰는 경우입니다. 계정이 다르면 다음이 달라집니다.

  • 자동 로그인은 A로 됩니다 — Codespace가 A의 토큰을 자동으로 넣어 주므로, 처음 copilot을 실행하면 B가 아니라 A로 인증됩니다(Step 2).
  • 승인은 B가 로그인된 브라우저에서 합니다 — device code를 A가 로그인된 브라우저에서 승인하면 A로 등록됩니다(Step 3).
  • B의 토큰이 A 소유 Codespace에 저장됩니다 — 그래서 정리도 계정별로 나뉩니다. Codespace 삭제는 A에서, (선택) B의 앱 승인 취소는 B에서 합니다(Step 6).

두 계정이 같은 경우는 이번에 검증하지 않았습니다.

계정이 가이드의 표기하는 일
Aaccount-aCodespace의 소유자입니다. VM·저장소 사용량이 A에 잡히고, Codespace 안에는 A의 토큰이 자동으로 들어옵니다(GITHUB_TOKEN).
Baccount-bCopilot CLI에 로그인하는 계정입니다. Copilot 라이선스가 있어야 하며, 모델 호출 사용량은 B에 반영됩니다.

본문의 account-a·account-b는 실제 GitHub 사용자명을 가린 표기입니다. 따라 하실 때 화면에는 각자의 계정명이 표시됩니다.

준비물

  • A로 로그인된 브라우저 — Codespace 생성·삭제용
  • B 전용 브라우저 창 — 다른 브라우저 프로필 또는 시크릿 창. A와 같은 브라우저에서 승인하면 A로 등록됩니다(Step 3).
  • B의 2단계 인증 수단 (인증앱 6자리 코드 등)
  • (선택) Azure 구독 — Azure MCP로 실제 리소스를 조회·변경할 때만 필요
조직 정책 문서 기준B의 Copilot을 조직·엔터프라이즈가 제공하는 경우, 관리자가 Copilot CLI를 비활성화했다면 로그인 후에도 사용할 수 없습니다.

1계정 A로 Codespace 만들기 검증됨

계정 A로 로그인한 브라우저에서 진행합니다. 약 1분.

  1. github.com/codespaces를 엽니다. 우측 상단 아바타가 A인지 확인하세요. 처음이면 목록이 비어 있습니다(All 0).
  2. Explore quick start templates에서 Blank → Use this template를 누릅니다.
  3. 새 탭에서 웹 VS Code가 열립니다(약 20초). 폴더 신뢰 창이 뜨면 Trust Folder & Continue를 누릅니다.
  4. 하단 터미널(Ctrl+`)의 프롬프트에 A의 사용자명(@사용자명 형태)이 보이면 A 소유 Codespace입니다.
  5. 환경을 확인합니다.
    Codespace 터미널 
    grep PRETTY_NAME /etc/os-release
node -v && npm -v
command -v copilot gh
    실제 출력
    PRETTY_NAME="Ubuntu 24.04.5 LTS"
v24.22.2
11.19.1
/usr/local/bin/copilot
/usr/bin/gh

    기본 이미지에 copilot(1.0.105)과 gh가 이미 들어 있고, Azure CLI(az)는 없습니다. 2 vCPU · RAM 7.8GiB 였습니다.

수명·비용 문서 기준Codespace는 30분 동안 입력·터미널 출력이 없으면 자동 중지되고(최대 수명 12시간), 중지 후 30일간 쓰지 않으면 삭제됩니다(기본값). 켜져 있는 동안은 사용 시간이 A에 과금(무료 한도 포함)됩니다.

3계정 B로 Copilot 로그인 검증됨

A와 B가 서로 다른 계정이라서 필요한 단계입니다. Codespace는 원격 환경이라 device code 방식으로 로그인합니다. 코드는 터미널에서 보고, 승인은 B 전용 브라우저에서 합니다.

① Codespace 터미널/login → 일회용 코드 XXXX-XXXX 표시
→
② B 전용 브라우저github.com/login/device 에 코드 입력, 계정 B로 승인
→
③ Codespace 터미널Signed in successfully as account-b!
  1. CLI 안에서 로그인을 시작합니다. 첫 질문은 1. GitHub.com, 두 번째는 1. Sign in with a device code (recommended)를 고릅니다.
    Copilot CLI 안 
    /login
    실제 출력
    ◎ Waiting for authorization...
Enter one-time code: XXXX-XXXX at https://github.com/login/device
Press any key to copy to clipboard and open browser...
    아무 키도 누르지 마세요키를 누르면 CLI가 브라우저를 열어 주는데, 그 브라우저는 A가 로그인된 창이기 쉽습니다. 이 실습의 첫 시도에서도 A 브라우저에 device 페이지가 열려 A로 승인됐습니다. 코드만 확인하고 B 브라우저에서 주소를 직접 여세요.
  2. B 전용 브라우저(다른 프로필·시크릿 창)에서 github.com/login/device를 엽니다.
    • 계정 B로 로그인하고, 우측 상단 계정명이 B가 맞는지 확인합니다.
    • 2단계 인증에서 QR 코드·패스키 창이 뜨면 닫고(Esc), 코드 입력 방식(예: 인증앱 6자리 코드)을 선택합니다. 문구는 계정 설정에 따라 다릅니다(예: Use your authenticator app).
    • 터미널에 표시된 코드를 입력하고 Authorize GitHub Copilot CLI를 누릅니다.
  3. 터미널에서 토큰 저장 방식을 묻습니다. Codespace에는 키체인(keyring)이 없어서 나오는 질문입니다. 일회용 Codespace라면 1. Yes를 선택합니다.
    실제 출력
    ! System vault not available
The recommended secure storage (keychain, keyring, or credential manager) could not be found or
accessed. You may need to install or configure one.
Storing the token in the config file saves it as plain text, which is insecure. If you decline,
sign-in will be cancelled and no account state will be changed.
Store token in plain text config file?
❯ 1. Yes, store in plain text (insecure)
  2. No, cancel sign-in

    토큰은 ~/.copilot/config.json에 평문으로 저장됩니다. Step 6에서 Codespace를 삭제하면 함께 사라집니다.

  4. 성공 메시지를 확인하고, (active)가 B로 바뀌었는지 꼭 확인합니다.
    Copilot CLI 안 
    /user list
    실제 출력
    ● Signed in successfully as account-b!
Available users:
  account-a — GitHub.com
  account-a (via gh) — GitHub.com
  account-a (via GITHUB_TOKEN) — GitHub.com
  account-b — GitHub.com  (active)

    A 항목 3줄은 Codespace가 주입한 토큰·gh 로그인이라 계속 보이는 것이 정상입니다. 두 계정이 함께 보이지만 현재 사용 중인 계정은 (active)인 B뿐입니다. 현재 사용 계정은 /user show, 전환은 /user switch입니다.

흔한 실패: B로 로그인했는데 A로 등록됨

두 계정이 다르다는 점을 놓치면 생기는 실수입니다. A가 로그인된 브라우저에서 코드를 승인하면 Signed in successfully as account-a!가 나옵니다(실제 재현). Esc로 대기를 취소하고 /login부터 다시 하되, 이번에는 B 전용 브라우저에서 승인하세요. 항상 /user list의 (active)로 결과를 확인합니다.

코드 유효시간 문서 기준device code는 발급 후 약 15분 동안 유효합니다(GitHub OAuth device flow 기본값). 만료되면 Esc 후 /login으로 새 코드를 받으세요. 환경변수 COPILOT_GITHUB_TOKEN → GH_TOKEN → GITHUB_TOKEN을 직접 export하면 그 토큰이 로그인한 계정보다 우선합니다. Codespace가 자동 주입한 GITHUB_TOKEN은 /login 계정을 덮어쓰지 않습니다(이번 검증에서도 B가 active).

4MCP 3종 설치 검증됨

Codespace 터미널에서 copilot mcp add로 등록합니다. 설정은 ~/.copilot/mcp-config.json에 저장됩니다.

서버유형설치인증도구 수컨텍스트 부담
microsoft-learn원격 HTTPURL 등록없음3약 0.8k 토큰
azure로컬 stdio (@azure/mcp)npx 명령 등록리소스 접근 시 Azure 로그인73약 14.9k 토큰
playwright로컬 stdio (@playwright/mcp)npx --headless + Chrome 설치없음25약 4.0k 토큰

도구 수·토큰은 /mcp 대시보드와 세션 로그에서 관측한 값입니다. 내장 GitHub MCP 서버(5개 도구, 약 1.1k)는 따로 설치하지 않아도 같이 보입니다.

4-1. Playwright용 Chrome 설치 (한 번만)

Codespace에는 화면이 없으므로 --headless로 띄우지만, 브라우저 자체는 설치돼 있어야 합니다. Chrome만 설치해도 동작했습니다(약 88초).

Codespace 터미널 
npx -y playwright install chrome
google-chrome --version
실제 출력
Google Chrome 156.0.8078.79

WARNING: … without first installing your project's dependencies 박스는 무시해도 됩니다. 설치 중 Switching to root user to install dependencies...가 나오며 시스템 패키지를 root 권한으로 설치합니다(Codespace에서는 비밀번호 없이 진행). Chrome은 /opt/google/chrome에 설치됩니다. 구동 확인(선택):

Codespace 터미널 
google-chrome --headless=new --disable-gpu --dump-dom https://example.com 2>/dev/null | grep -o '<title>.*</title>'
실제 출력
<title>Example Domain</title>

4-2. 3개 서버 등록

Copilot CLI가 켜져 있는 터미널은 그대로 두고, 새 터미널 탭(＋)을 열어 실행합니다.

Codespace 터미널 (Copilot CLI 밖) 
copilot mcp add --transport http microsoft-learn https://learn.microsoft.com/api/mcp
copilot mcp add azure -- npx -y @azure/mcp@latest server start
copilot mcp add playwright -- npx -y @playwright/mcp@latest --headless

4-3. 등록 확인

Codespace 터미널 
copilot mcp list
실제 출력
User servers:
  microsoft-learn (http)
  azure (local)
  playwright (local)
Builtin servers:
  github-mcp-server (http)

Copilot CLI 안에서 /mcp를 열면 4/4 enabled로 보입니다(azure · GitHub MCP Server · microsoft-learn · playwright). 목록이 바로 갱신되지 않으면 대시보드에서 r(refresh)을 누르거나 CLI를 다시 시작하세요.

저장된 설정 파일 보기 (~/.copilot/mcp-config.json)
{
  "mcpServers": {
    "microsoft-learn": { "tools": ["*"], "type": "http", "url": "https://learn.microsoft.com/api/mcp" },
    "azure":      { "tools": ["*"], "type": "local", "command": "npx", "args": ["-y", "@azure/mcp@latest", "server", "start"] },
    "playwright": { "tools": ["*"], "type": "local", "command": "npx", "args": ["-y", "@playwright/mcp@latest", "--headless"] }
  }
}

파일을 직접 편집하거나, CLI 안 /mcp add 폼(Server Name · Type · Command · Tools 입력 후 Ctrl+S)으로도 같은 결과를 얻습니다. 문서 기준

서버별 메모

microsoft-learn

  • 주소: https://learn.microsoft.com/api/mcp (Codespace에서 HTTP 200 응답 확인)
  • 도구: microsoft_docs_search 등 3개
  • 대안: /plugin install microsoftdocs/mcp — MCP + 스킬 3종 문서 기준

azure

  • @azure/mcp@latest가 현재 4.0.0-beta.4입니다. 재현성이 필요하면 버전을 고정하세요.
  • 리소스 조회·변경에는 Azure 로그인이 필요합니다. Codespace에는 az가 없어 별도 설치가 필요합니다(이번 실습 범위 밖).
  • 서버 옵션 --read-only, --namespace, --tool이 존재합니다(server start --help로 확인, 동작은 미검증).

playwright

  • --headless는 창 없이 실행(기본은 headed)합니다.
  • Chrome이 기본 브라우저입니다. 번들 Chromium 없이 Chrome만 설치해도 호출이 성공했습니다.
  • 비-root 사용자라 --no-sandbox가 필요 없었습니다. root·컨테이너에서는 필요할 수 있습니다.
  • 매번 깨끗한 프로필이 필요하면 --isolated 문서 기준
Azure MCP는 처음엔 읽기 전용으로 옵션 존재만 확인

로그인한 Azure 계정의 권한으로 동작하므로, 실제 구독을 연결할 때는 --read-only로 시작하는 것이 안전합니다. 다시 등록하려면 먼저 지웁니다.

copilot mcp remove azure
copilot mcp add azure -- npx -y @azure/mcp@latest server start --read-only

컨텍스트가 빨리 찬다면 안 쓰는 서버는 copilot mcp disable azure로 끌 수 있습니다(remove·disable은 문서 기준).

5동작 확인 검증됨

B 계정으로 실제 모델 호출 + MCP 도구 호출까지 확인합니다. 대화형 copilot에 같은 문장을 입력해도 됩니다(승인 프롬프트에서 1. Yes).

5-1. Microsoft Learn

Codespace 터미널 
copilot -s -p "Use the microsoft-learn MCP server to find the Microsoft Learn page titled 'Get started with the Microsoft Learn MCP Server'. Reply in one line with the title and URL." --allow-tool='microsoft-learn'
실제 출력 · 17초 · 호출된 도구: microsoft_docs_search
Get started with the Microsoft Learn MCP Server — https://learn.microsoft.com/training/support/mcp-get-started

-p는 한 번만 실행하는 비대화형 모드, -s는 부가 출력 없이 답만 출력, --allow-tool='서버이름'은 그 MCP 서버의 도구를 묻지 않고 허용합니다.

5-2. Playwright (headless)

Codespace 터미널 
copilot -s -p "Use the playwright MCP server to open https://example.com and tell me the page title. Reply in one line." --allow-tool='playwright'
실제 출력 · 13초 · 호출된 도구: browser_navigate
The page title is "Example Domain".

5-3. Azure (대화형으로 실행)

Copilot CLI 안 (copilot 실행 후 입력) 
Use the azure MCP server to get the Azure best practices for deploying to Azure Functions. Reply in ONE short line.

승인 프롬프트가 세 번 나옵니다. 모두 1. Yes를 고릅니다.

  1. Do you want to use this tool? — Azure Best Practices from azure
  2. MCP Server "azure" is requesting to perform an inference request. — 서버가 CLI의 모델 호출을 요청합니다(MCP sampling). “This will utilize your Copilot plan requests.” 문구대로 B의 Copilot 요청을 소모합니다.
  3. 두 번째 도구 호출을 다시 묻습니다. 이후 {"status":200 … "bestPractices":[… 결과가 오고 모델이 한 줄로 요약합니다.
예시 응답 (모델 출력이라 매번 다름)
Use Flex Consumption (FC1) with functionAppConfig deployment storage; otherwise choose
Elastic Premium, enable authentication, private networking, and Application Insights,
and use Linux for Python Functions.
Azure MCP는 비대화형(copilot -p)에서 멈춥니다

위 2번(sampling) 승인을 받을 방법이 없어 응답이 오지 않습니다. 같은 프롬프트를 copilot -p로 실행하면 sampling.requested에서 대기하고, --allow-all-tools를 줘도 150초 타임아웃(exit 124)이었습니다. Azure MCP는 대화형 세션에서 쓰세요. 하단 상태줄에는 세션 사용량(예: Session: 0.21 AIC used)이 표시됩니다.

1번 프롬프트의 2. Yes, and don't ask again for tool … in this directory를 고르면 같은 폴더에서는 그 도구를 다시 묻지 않습니다.

6정리 검증됨

B의 토큰이 A 소유 Codespace의 ~/.copilot/config.json에 평문으로 저장돼 있습니다. 실습이 끝나면 Codespace를 삭제해서 정리하세요. Codespace는 A의 것이므로 삭제는 A 계정에서 합니다.

/logout으로는 토큰이 지워지지 않았습니다

문서에는 “로컬에 저장된 토큰을 제거한다”고 되어 있지만, 이 환경(Copilot CLI 1.0.105 · 토큰 평문 저장 · 자동 주입된 GITHUB_TOKEN 존재)에서는 /logout이 오류 없이 실행되고 입력창만 비워졌습니다. 3회 실행(CLI를 다시 시작한 뒤 1회 포함)해도 /user list에 B가 계속 (active)로 남았고, 저장 파일은 앞의 2회 확인에서 토큰 항목도 수정 시각도 그대로였습니다. 버전·환경에 따라 다를 수 있으니, 이 환경에서는 아래처럼 Codespace 삭제로 정리합니다.

  1. A 브라우저에서 github.com/codespaces를 열고 Owned by 아래에 지울 Codespace(여기서는 lonely ghost)가 맞는지 확인합니다. 이 실습에서는 1개뿐이었습니다.
  2. 카드 오른쪽 ⋯(Show more actions for codespace)를 누르고 메뉴에서 Delete를 고릅니다. 메뉴에는 Auto-delete codespace도 있는데, 이것은 보존 기간 설정(체크 표시)일 뿐 삭제 버튼이 아닙니다.
  3. 확인 창 Are you sure you want to delete lonely ghost?에서 이름을 확인하고 Delete를 누릅니다.
  4. 페이지를 새로고침해 Owned by 섹션이 사라졌는지 확인합니다. 삭제한 Codespace 주소(github.com/codespaces/<이름>)를 열면 404 Page not found가 나옵니다. 평문 토큰이 든 ~/.copilot/config.json도 Codespace와 함께 삭제됩니다.

선택: GitHub 쪽 승인 취소 문서 기준 · 미실행

토큰이 든 파일이 사라져도 GitHub의 GitHub Copilot CLI 앱 승인을 취소하는 것은 별개 작업입니다. B 브라우저에서 Settings → Applications → Authorized OAuth Apps → GitHub Copilot CLI → Revoke로 취소합니다.

다른 기기의 로그인에도 영향이 있을 수 있습니다이 앱 승인을 취소하면 같은 계정으로 다른 곳에 로그인해 둔 Copilot CLI도 쓰지 못하게 될 수 있습니다(공식 문서: “prevent it from being used elsewhere”). 이 실습 때문에 새로 만든 승인이 아니라면 취소하지 마세요.
