가입 방식을 하나 정하고, 초대 한도를 확인합니다.

초대 · 사용자명 명단이 있을 때

운영자가 People에서 직접 초대

  1. 참가자의 GitHub 사용자명(표시 이름이 아님)을 승인된 경로로 받습니다. 공개 이슈·공유 시트에 명단을 모으지 않습니다.
  2. 조직 People → Invite member → 사용자명 입력 → Invite → Role in the organization=Member → Send invitation.
  3. 참가자가 이메일 또는 조직 URL에서 직접 수락합니다. 수락 전에는 멤버가 아닙니다.

자가가입 · 명단이 없거나 인원이 많을 때

서명된 링크·QR로 참가자가 초대를 요청

  1. 승인된 운영 절차(예: Workshop Creator)로 자가가입 링크·QR을 받고 대상 조직·가입 가능 기간을 확인합니다.
  2. 링크·QR은 접근 권한을 담습니다. 참가자에게 비공개로 개별 전달하고 공개 이슈·저장소·화면 공유에 올리지 않습니다.
  3. 참가자는 본인 GitHub 계정으로 인증·동의한 뒤 초대를 요청하고, 발송된 초대를 직접 수락합니다.
링크를 쓸 수 없을 때 · 수동 접수

참가자가 승인된 문의 경로로 아래 문구를 보내면, 운영자가 사용자명을 확인한 뒤 위 초대 절차를 진행합니다. GitHub에는 사용자가 직접 가입을 신청하는 기본 양식이 없습니다.

MEMBERSHIP IS NOT A COPILOT SEAT

좌석을 배정하고, 정책과 비용을 확인합니다.

  1. 제공 방식: 조직의 Copilot Business/Enterprise 또는 기업의 Copilot access 등 승인된 방식을 확인합니다. 조직 생성·가입만으로 Copilot이 켜지지 않습니다.
  2. 좌석 배정: 조직 Settings → Copilot → Access → (표시되면) Allow this organization to assign seats → Start adding seats → Purchase for all members 또는 Purchase for selected members(Enable Copilot access for users and teams) → Purchase seats. 승인된 범위만 배정하고 목록에서 사용자명을 대조합니다.
  3. 정책: Copilot → Policies의 Copilot in the cloud가 켜져 있어야 브라우저 Copilot(github.com/copilot)을 쓸 수 있습니다. 2026.10.28부터 Copilot Chat in GitHub 등 개별 정책을 이 정책이 대체했고, 상위 엔터프라이즈 정책이 우선합니다. 허용 모델도 함께 확인합니다.
  4. CLI·앱 정책: 참가자가 Copilot CLI나 GitHub Copilot 앱을 쓴다면 Copilot → Policies에서 Copilot CLI 정책과 GitHub Copilot app 정책을 각각 확인합니다. 두 정책은 서로 독립이라 하나를 켜도 다른 하나가 켜지지 않으며, 앱 정책은 Business·Enterprise에서 기본값이 켜짐입니다. 엔터프라이즈가 “Enabled everywhere / Disabled everywhere”로 정했다면 조직에서 바꿀 수 없고, “Let organizations decide”라면 좌석을 주는 조직 중 한 곳 이상에서 CLI가 켜져 있어야 합니다. CLI는 좌석이 있어야 쓸 수 있습니다. 공식 CLI 관리 ↗ · 공식 앱 롤아웃 ↗
  5. 참가자 요청: 참가자가 Settings → Copilot의 Ask admin for access로 요청하면 조직 Settings → Access → Requests from members에서 승인합니다(공식 문서는 Copilot Business 기준). 기업이 조직에 Copilot을 켜 두지 않았다면 기업 Owner에게 요청합니다.
화면

Copilot → Access → 선택 멤버 좌석 (공식 화면)

  1. Users and teams 탭에서 참가자 사용자명을 검색해 추가하거나 Upload CSV로 한 번에 추가합니다.
  2. Continue to purchase → Purchase seats로 확정합니다.

완료 상태: 좌석 목록에 참가자 사용자명이 보입니다. 단순 가입 확인과 다릅니다.

REPOSITORY AND DEVELOPMENT ENVIRONMENT

질문만 할지, 코드를 다룰지, CLI·앱을 쓸지 정하고 환경을 준비합니다.

환경언제운영자 준비
브라우저 Copilot설명·오류 이해 질문만 할 때Copilot 좌석 + Copilot in the cloud 정책. 추가 설치는 없습니다.
Codespaces코드 수정·실행, 설치를 최소화할 때조직 Settings → Codespaces → General에서 Codespaces access(전체 / 선택 멤버·협업자)와 Codespace ownership(Organization / User 소유)을 정하고 예산을 확인합니다. 무료 플랜 조직은 결제할 수 없습니다.
로컬 VS CodeCodespaces를 쓰지 않을 때참가자 PC의 VS Code 설치·Copilot 로그인 안내와 저장소 clone 권한. 개인 장비 준비가 필요합니다.
Copilot CLI터미널에서 에이전트 동작을 체험시킬 때좌석 + Copilot CLI 정책 허용. 참가자 PC에서 설치(Windows winget · macOS/Linux Homebrew · npm은 Node.js 22 이상)와 GitHub 로그인(브라우저 또는 device code)이 되는지 확인합니다. Windows는 PowerShell 6 이상(PowerShell 7)이 필요합니다.
GitHub Copilot 앱데스크톱에서 여러 세션·PR 흐름을 체험시킬 때좌석 + GitHub Copilot app 정책 허용(CLI 정책과 별개). 참가자 PC의 설치 권한·Git·지원 OS(macOS·Windows·Linux)를 확인합니다. 설치 파일은 gh.io·github.com에서 release-assets.githubusercontent.com으로 내려받아지므로 교육망에서 막히지 않는지 봅니다.
  1. 접근: 팀·저장소 권한이 참가자에게 필요한 만큼만 부여되었는지 확인합니다.
  2. 내용: 브랜치, README(설치·실행·종료), dev container와 실행 명령이 실제로 동작하는지 확인합니다.
  3. 대체 경로: Codespaces를 쓰지 않는 과정이면 로컬 VS Code, Copilot CLI·앱, 또는 브라우저 질문만 하는 경로를 인계표에 명시합니다. 참가자 PC에 설치가 막힐 때의 대안(브라우저·Codespaces)도 함께 정합니다.
  4. 네트워크: 교육망이 github.com·Copilot 서비스(*.githubcopilot.com)와 설치 파일 경로를 막지 않는지 확인합니다. 허용 목록은 공식 Copilot allowlist reference ↗를 따릅니다.
Codespaces는 Copilot 좌석과 별도 과금입니다. 기본값은 30분 유휴 시 자동 정지, 정지 후 30일이 지나면 자동 삭제이며 정지 상태에서도 저장 공간 비용이 남습니다. 예산이 소진되면 새로 만들거나 재개할 수 없고 변경 사항을 브랜치로 내보내기만 할 수 있습니다. 공식 소유·비용 기준 ↗

ALIGN THE DATES

링크·초대·행사·삭제 일정을 같은 시간대로 맞춥니다.

기간뜻주의
자가가입 링크의 시작·만료초대를 요청할 수 있는 시간행사일·조직 삭제일과 같다고 가정하지 않습니다. 만료되면 새 안내를 발급합니다.
발송된 GitHub 초대참가자가 수락할 수 있는 시간미수락 초대는 7일 후 만료됩니다. 링크가 유효해도 별도 수락이 필요합니다.
행사 시각실습이 진행되는 시간시간대(예: KST)를 함께 안내합니다.
임시 조직 삭제 예정일저장소·행사 콘텐츠가 정리되는 일정링크 연장·재발급만으로 조직 수명이 늘지 않습니다. 새 링크가 이전 링크를 자동 폐기한다고 가정하지 않습니다.
특별 가입 기간의 변경은 승인된 운영 절차로 처리하고, 변경 후에는 참가자 안내의 모든 날짜를 다시 대조합니다.

GO / NO-GO

인계 전에, 새 개인 계정으로 전체 흐름을 리허설합니다.

운영자 계정이 아닌 허용된 테스트용 개인 GitHub 계정으로 진행합니다. 생성 성공 메시지나 브라우저의 일반 답변만으로 통과시키지 않습니다.

01 · 가입

초대(또는 자가가입) → 수락 → Organizations에서 멤버십 확인. 2FA·이메일 요구까지 확인합니다.

02 · 좌석

같은 사용자명이 Copilot Access 목록에 있고 Settings → Copilot에서 조직 권한이 보입니다. 개인 Free/Pro 표시로 판단하지 않습니다.

03 · 브라우저

github.com/copilot에서 질문 1개에 응답이 옵니다. 차단되면 Copilot in the cloud 정책을 확인합니다.

04 · 환경

인계표에 적은 환경마다 같은 계정으로 질문 1개를 확인합니다. Codespaces·VS Code는 실제 저장소·README를 열고, Copilot CLI는 새 PC에서 설치 → /login → 질문까지, Copilot 앱은 설치 → 로그인 → Chats 질문까지 한 번씩 해 봅니다.

05 · 비용·한도

Codespaces 소유·예산, 허용 모델·AI Credits, 개인 유료 플랜 영향 안내를 확인합니다.

06 · 일정·인계

링크 만료·초대 7일·행사·삭제 일정을 대조하고 인계 템플릿과 지원·대체 담당을 확정합니다.

테스트 계정으로 가입 → 좌석 → 응답이 모두 성공

CLI·앱을 쓴다면 해당 정책 허용과 설치·로그인·질문까지 테스트 PC에서 성공

미확인 항목이 없거나 승인된 대안이 정해짐

리허설 계정은 참가자에게 배정하지 않고, 좌석 정리 방법을 정함

DIAGNOSE BEFORE WORKING AROUND

가입 → 좌석 → 정책 → 환경 순서로 원인을 가립니다.

참가자의 GitHub 사용자명·대상 조직·진행 경로·선택 환경·발생 시각과 민감 정보를 가린 오류만 받습니다. 암호·2FA 코드·토큰·서명된 링크는 받지 않습니다. 참가자용 대응표는 참가자 가이드에 있습니다.

증상운영자 확인·조치피해야 할 해결책
신청했는데 초대가 오지 않음자가가입은 사이트의 인증·동의·초대 요청 상태를, 수동 접수는 사용자명·승인 상태를 확인합니다. People의 대기 중 초대에서 실제 발송·실패를 대조합니다.공개 채널에 링크나 사용자명 목록 게시.
자가가입 링크 오류·기간 만료최신 링크·조직·시작/만료 시각·시간대를 확인하고 승인된 절차로 새 안내를 발급합니다.URL의 서명·날짜 수정, 원문 링크 공개.
자가가입은 성공했는데 조직이 안 보임요청 성공과 멤버십은 다릅니다. 참가자가 같은 계정으로 이메일·조직 URL에서 초대를 수락했는지 확인합니다.운영 SSO/EMU 계정으로 대신 수락.
초대가 안 보임·만료됨·이메일 불일치스팸함과 초대받은 계정을 확인합니다. 7일 만료이거나 이메일이 계정의 인증된 이메일과 다르면 사용자명으로 재초대합니다.다른 사람의 이메일 인증을 대신 처리.
2FA·SSO 때문에 가입 안 됨참가자가 GitHub 2FA를 먼저 설정하고 승인된 SSO 절차를 따르도록 안내합니다.인증 코드 공유, 정책 우회.
가입했는데 Copilot이 없음Copilot → Access에서 같은 사용자명의 좌석 상태를 확인하고 요청 대기면 Requests from members에서 승인합니다. 참가자는 새로고침·재로그인합니다.참가자에게 개인 유료 구독 권유.
브라우저 Copilot이 차단됨조직·상위 엔터프라이즈의 Copilot in the cloud 정책과 허용 모델·사용 한도를 확인합니다.정책 우회.
브라우저는 되는데 IDE에서 안 됨VS Code/Codespaces의 로그인 사용자명, Accounts → Manage Extension Account Preferences → GitHub Copilot Chat의 계정, 조직 정책·네트워크를 확인합니다.개인 Free 계정 로그인을 조직 권한으로 착각.
Codespaces 없음·저장소 접근 불가·결제 요구Codespaces access 대상, 저장소 팀 권한, Codespace ownership·예산을 확인합니다.개인 카드 등록, 공개 저장소 무단 복제.
CLI에서 정책 거부·로그인 실패Copilot → Policies의 Copilot CLI 정책과 상위 엔터프라이즈 정책(“Let organizations decide”면 좌석을 주는 조직 중 한 곳 이상에서 켜져 있어야 함), 같은 사용자명의 좌석을 확인합니다. 참가자에게는 /user로 로그인한 계정을 확인하게 합니다.참가자에게 토큰(PAT) 발급·공유를 요구하거나 개인 유료 구독 권유.
앱 설치·로그인 후 플랜 가입 화면GitHub Copilot app 정책(CLI와 별개), 좌석, 로그인한 사용자명을 확인합니다. 회사 PC의 설치 제한·네트워크 차단이면 대체 환경(브라우저·Codespaces)을 안내합니다.참가자가 개인 플랜 가입이나 자체 API 키(BYOK) 입력으로 우회.
개인 Copilot 구독이 바뀜조직 좌석 배정 시 개인 Pro·Pro+·Max가 자동 취소·일할 환불됩니다. Settings → Copilot과 공식 라이선스 안내로 확인합니다.좌석을 회수하면 개인 플랜이 복구된다고 약속.

APPROVED CLEANUP · KEEP THE EVIDENCE YOU NEED

산출물 보존을 확인한 뒤 좌석·환경·조직을 정리합니다.

  1. 완료 확인: 참가자의 완료 상태·실패 항목·지원 이슈를 운영 대장에 기록합니다.
  2. 보존: 남길 변경이 허용된 브랜치에 push되었는지, 임시 조직 밖 보존이 필요하면 승인된 비공개 위치로 옮겼는지 확인합니다. 코드·고객 자료를 임의로 공개하지 않습니다.
  3. Codespaces: 참가자의 Stop을 안내하고 남은 Codespace를 확인합니다. 브라우저 탭을 닫아도 유휴 제한(기본 30분)까지 실행되며, 정지 후에도 저장 공간 비용이 남고 기본 30일 뒤 자동 삭제됩니다.
  4. 좌석 회수: 승인된 시점에 회수합니다. 현재 청구 주기가 끝날 때까지 과금될 수 있고, 개인 유료 플랜은 자동 복구되지 않습니다.
  5. 조직·저장소: 임시 조직 삭제 일정에 맞춰 삭제하거나 보존합니다. 임시 조직 삭제는 개인 GitHub 계정 삭제와 다릅니다.
  6. 운영 요청 종료: 조직 삭제와 연동된 환경에서는 단순 상태 정리로 요청을 닫지 말고 보존·종료 승인을 먼저 확인합니다.
이 문서는 초대·구매·권한 회수·삭제를 자동 실행하지 않습니다. 개인 GitHub 계정은 삭제하지 않습니다.

기준일 2026.11.10 · 공식 문서의 메뉴 이름·한도·정책은 바뀔 수 있으므로 개최 전에 다시 확인합니다. 워크샵 준비 흐름은 Bootstrap 운영 가이드(운영자 전용 접근·SSO가 필요할 수 있음)를 참고했으며, 원문 코드·이미지·내부 식별자·비밀 값은 복사하지 않았습니다. 이 페이지는 특정 행사의 전체 동작을 검증한 기록이 아닙니다.
